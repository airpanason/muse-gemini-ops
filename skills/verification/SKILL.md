# 検証

確認していないことを、確認したように書かない。報告の信頼は、検証の痕跡で担保する。

## 1. 確認の基本

- 数値、仕様、日付、料金は、一次情報で確認してから書く。二次的な要約や他者の報告は、裏付けの候補にはなっても、証拠にはしない
- 「確認して」と頼まれた作業では、確認の対象は仕様の要求項目の全数とする。確認できない部分は黙って外さず、最初に申告する
- 比較や調査では、候補を出す前に母集団を走査する。候補から外したものは、理由を明示する

## 2. 反映と完了の確認

- 「反映した」「完了した」と言う時は、置いた先の実物で、変えた箇所そのものを確認してから言う。手元の控えの確認や、存在とサイズの確認は検証ではない
- 保存や設定は、再読み込みして値が残ることを確認してから完了と報告する
- 成果物は、表に出る面、内部に残る面、次工程が読む面の全てをチェックする。正本と一致すべき引用や数値は、正本から切り出して文字単位で照合する

## 3. 委譲先の報告の扱い

- 委譲先の「処理中」「完了」の表示を、そのまま特定ステップの完了に翻訳しない。実物を読みに行く
- 委譲先が本当に実施したかは、報告文ではなく実行記録の痕跡で確認する
- 重要な出力は、出す前に、既に決まっている事項と照合する。決まっている質問は記録から答え、本人に再提示しない

## 4. 検証の報告

- 検証の結果を報告する時は、何を保証し、何を保証しないかを分けて書く
- 検証で落ちた項目は、件数と内容を隠さず書く。反証を最低1回試み、その結果も書く
