# 資源消費の上限

消費が伴う作業は、上限を書いてから始める。上限を書けない作業は開始しない。

## 1. 開始前に書くこと

- 上限を、回数ではなく消費量の単位（金額、クレジット、トークン等）で書く。金額換算も添える
- 計量の方法（どこで、どの単位で消費を読むか）を書く
- 停止条件を書く。上限に達したら自動で止まり、保留して、本人へ知らせる
- 上限を超える必要が出た場合は、事前に本人の承認を取る。自動で有料枠へ切り替えない

## 2. 実施中の扱い

- 消費は実施中に読む。終わってから合計を見て驚く形にしない
- 上限への到達が見えたら、残りの作業を止めて報告する。報告には、消費した量、上限、止めた時点の状態を含める
- 無料枠の超過分が少額でも、管理の失敗として扱う。金額の大小で扱いを変えない

## 3. 報告

- 終了時は、消費量の実績と上限との差を報告する
- 上限に達して止まった場合は、失敗ではなく停止条件が働いた結果として報告し、続けるかどうかは本人の判断に委ねる

## 4. 実行回数と並行数の制御（RSC）

- RSC-01（再試行上限）: 同一処理の再試行は 3回 までとする。上限を超えた場合は停止し、失敗として報告する
- RSC-02（進展なし停止）: 同一の操作で同一の結果が 2回 連続した場合は、進展なしとみなして停止し、報告する
- RSC-03（並行上限）: サブエージェントの並行実行は 3件 までとする。上限を超える委譲は直列化する
- RSC-05（長大入力の扱い）: 異常に長い入力は文字数では一律に切らない。他の文脈を圧迫する場合は、ファイル化または分割・要約してから処理する
- RSC-06（重複確認）: 重い処理は、起動前に同一処理の実行中・完了済みでないかを確認する
- RSC-07（急増検知）: 利用枠の急増を検知したら、新規の仕組みは足さず、そのまま報告する
- 例外と再開: 進展が確認できる長時間処理（処理量、出力、ログで判定）は上限の対象外とする。停止した処理を自動で再開せず、再開は本人の判断による
