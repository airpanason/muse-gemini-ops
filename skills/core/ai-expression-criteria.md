# AI表現の回避・受容基準（設計物・全生成物共通）

- 位置づけ: スキル `core` §1「言葉と書き方」の別紙
- 原則: 「回避基準」に該当する表現は使わず、具体的な事実・数値・動作（動詞）で記述する。ただし、「受容基準」に該当し、他の表現に言い換えると意味が不正確になるか過度に回りくどくなる場合のみ使用を認める

1. メタ宣言・前置き（「以下で説明します」「結論から言うと」「本設計書では〜を解説します」）
   - 回避: 単なる段落の導入や回答の枕詞として入っている場合（削って1文目から結論や仕様を書く）
   - 受容: 長大な文書の冒頭で、対象読者や適用範囲（スコープ）を明示的に定義する必要がある場合
2. 抽象的な評価・万能語（「最適な」「効果的な」「重要な」「劇的に」「シームレスな」「堅牢な」「不可欠」）
   - 回避: 具体的な仕様や動作の代用として使っている場合（具体的な数値・条件・動作に置き換える）
   - 受容: 具体的な構成や数値を示した上で、設計方針の総称として一言でまとめる場合
3. 硬直した接続詞・AI頻出語（「〜において」「〜の観点から」「多岐にわたる」等の連発）
   - 回避: 通常の助詞（「〜で」「〜では」）や具体的な内訳（「3種類ある」等）で書ける場面
   - 受容: 設計上の条件分岐や評価軸を厳密に限定しないと誤読される場合
4. 事なかれ主義の保険・逃げ文句（「一概には言えませんが」「場合によります」「状況に応じて」「一般的に」「〜が求められます」）
   - 回避: 設計判断や結論を曖昧にして読み手に委ねている場合（条件ごとの分岐や判断基準を明記して言い切る）
   - 受容: 現時点で未確定の外部制約があり、「条件Xが確定するまでは未定」と事実として記載する場合
5. 構造のテンプレ化（「太字項目名：説明」の連打、均一すぎる箇条書き、同一語尾の3連以上）
   - 回避: 背景説明や設計の意図（なぜ他案を捨ててその案を選んだか）まで細切れの箇条書きにし、単調になっている場合
   - 受容: パラメータ定義、手順書、合否条件、報告の要点など、一覧性と検索性を最優先すべき箇所
6. 同義語の反復・末尾の抽象まとめ（「つまり」「要するに」「総じて」「以上のように〜が重要です」の再掲）
   - 回避: 同じ内容を別の言葉で繰り返しているだけの場合、または段落を閉じるためだけの要約
   - 受容: 複数の設計案を比較した末尾で、最終的な採用案と理由だけを1文で確定させる場合
7. 意味を変える推敲の禁止
   - 推敲では原文の主張・比重・言い切りの強さ・文の働きを変えず、原文にない情報（主語・理由・条件・数値・例）を足さない。推量を断定に変えない
   - 身体性のある比喩動詞は、何がどう変わったかを書く平易な事実記述に直す
   - 間を作るだけの読点は足さない。誤読を防ぐ読点と、並んだ語句や条件・理由の切れ目の読点は残す
   - 意味を確定できない箇所は推測で埋めず、原文のまま残す。確認事項は読者向けの本文に入れず、本文の後に分けて添える
