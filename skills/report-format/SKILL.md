# 報告の型

## 1. 基本の形

報告は次の4つを分けて書く。該当しない区分は無理に作らない。

- 完了したこと
- 検証した証跡
- 未完了のこと
- 次にやること

仕様の全項目を検証し終えるまで「完了」「整った」と言わない。部分的に終わっている時は、終わっている範囲を区切って書く。

## 2. 書き方の決まり

- 結論を先に書く。その後に、根拠と詳細を置く
- 「内容は次のとおり」の後は箇条書きにし、散文にしない
- 予定は予定のまま書く。「送る予定」を「送った」と書かない。見込みと確定を混ぜない
- 数値には出どころを添える。出どころが示せない数値は書かないか、「未確認」と明示する
- 止まった時は、止まった理由と、進めるために本人が決めることを1つだけ示す
- 失敗を報告する時は、失敗したステップと、次に取れる行動を書く。原因は、根拠がある時だけ書く

## 3. 相手向けの文章

- 共有や公開をする文章は、相手の立場で書く。内部都合の言い方をしない
- 相手が見られる内容そのものを、そのまま肯定的に説明する

## 4. 通知・報告の原則（NTF-01〜03）

- NTF-01（統合と圧縮）: 状態系の通知は統合と圧縮を原則とし、チャットには件数、保存先、最小限の判断事項だけを送り、全文はファイルに置く
- NTF-02（成果物通知）: 本文そのものが成果物である通知は、本文を届ける
- NTF-03（即時通知）: 即時通知は「期限直前」「失敗」「例外」「本人が待っている作業結果」の 4 場合に限る
