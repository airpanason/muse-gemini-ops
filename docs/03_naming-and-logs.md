# 03. 命名とログ — フォルダ構成・命名規則・フラグメントログ設計

## 3.1 フォルダ構成

内容は次のとおり。

```text
<shared-drive>/
  reference/               # 参照専用
  primary-work/            # Primary の作業場
  primary-to-secondary/    # Primary → Secondary の受け渡し専用
  shared-canonical/        # 正本（運用メモ・スキル・連携物）
    operations-memo.md
    PENDING-UPDATES.md
    log-primary.md         # Primary の作業ログ台帳（Secondary が維持）
    log-secondary.md       # Secondary の作業ログ要約
```

## 3.2 受け渡しファイルの命名規則

ファイル名の接頭辞で種類を示す。

| 接頭辞 | 種類 |
| :---- | :---- |
| `edit-page_` | 公開ページの編集案 |
| `edit-draft_` | 案件・文書の下書き |
| `incident_` | インシデント台帳への起票依頼 |
| `chg_` | 運用メモ・スキル・仕様書等の改訂案（変更管理の対象） |
| `incident-chg_` | インシデント起票と改訂案の両方を含むもの |
| `fig_` | 図の成果物（画像ファイル） |
| `fig-req_` | 図の作成依頼（Secondary → Primary） |
| `revise-req_` | 差し戻し・作り直しの依頼 |
| `final-check-req_` | 最終確認とタグの依頼 |
| `memo_` | 確認結果・タグ等の返信メモ |
| `log-frag_` | 作業ログの断片 |
| （接頭辞なし） | 通常の受け渡し物 |

## 3.3 図の受け渡しの命名

内容は次のとおり。

- 依頼（Secondary → Primary）は `<shared-drive>/shared-canonical` へ `fig-req_<YYYY-MM-DD>_<記事スラッグ>_<連番2桁>.md` で置く。中身に対象の記事・入れる章・何を表す図か・縦横比などを書く
- 成果物（Primary → Secondary）は受け渡しフォルダへ、依頼と同名で接頭辞だけを `fig_` に替えた画像ファイルで置く（例: 依頼 `fig-req_2026-01-15_example-post_01.md` に対して、成果物は `fig_2026-01-15_example-post_01.jpg`）
- カバー画像（見出し画像）は連番の代わりに末尾の識別子で区別する。依頼は `fig-req_<YYYY-MM-DD>_<記事スラッグ>_thumb.md`、成果物は `fig_<YYYY-MM-DD>_<記事スラッグ>_thumb.<拡張子>` とする
- カバー画像の依頼には、対象の記事・記事の主題・縦横比（16:9 横長）・文字有無の方針を書く

## 3.4 フラグメントログ設計

Primary は正本のログ台帳を直接編集・上書きしない。1作業ごとに断片ファイル `log-frag_<YYYYMMDD-HHMM>_<スラッグ>.md` を受け渡しフォルダへ新規に置く。

断片の中身は表形式を使わず、次の6項目をキー・バリュー形式（箇条書き）で書く。

- 日時
- 依頼の種別
- 依頼の要約（1行）
- 返したもの
- 結果
- 往復回数

配置前の自己チェック4点（命名、作業ログの現行版の読み直し、秘密情報の混入、改訂案の3要素）の結果も、断片に含める。

Secondary は定期確認で、入口の機械検査を通した断片を台帳 `log-primary.md` へ統合し、処理済みの断片に `done-` を付ける。台帳の維持は Secondary が行い、Primary は参照のみとする。

作業ログの粒度は、何を依頼され、何を返し、どう決まったか、までとする。会話の実質と個人の文脈は書かない。

## 3.5 入口の機械検査（lint）

Secondary は受け渡し物の取り込み前に、機械判定できる項目をスクリプトで検査する。

| ID | 検査 |
|---|---|
| LINT-01 | 命名・形式の適合（`fig_` の命名規則、カバー画像の縦横比 16:9、同名 `fig_` の重複） |
| LINT-02 | 作業ログ台帳の健全性（単一ファイル、版の単調増加、行数の非減少、全行6列） |
| LINT-03 | 秘密情報・個人情報のパターン走査 |
| LINT-04 | 改訂案の必須要素（変更前・変更後・影響）の有無 |

不合格のファイルは取り込まず、理由を本人へ報告する。
