# 01. アーキテクチャ — 役割・権限境界・正本管理

## 1.1 二役モデル

内容は次のとおり。

- **Primary AI（主系）**: 判断・計画・起案・調査・下書き作成。データの無い単発作業だけを扱う
- **Secondary AI（副系）**: 実行基盤と正本への最終反映。定常ジョブ、ブラウザ操作、ファイル連携、デプロイ、台帳管理、月次報告を担当する
- **本人**: 最終承認と条件決定。説明責任（A）は常に本人に残る

どちらか一方だけでは回らない設計にする。Primary は実行手段を持たず、Secondary は判断の最終決定をしない。

## 1.2 RACI

| 意思決定・作業 | Primary | Secondary | 本人 |
| :---- | :---- | :---- | :---- |
| データの無い単発作業（調査・要約・下書き） | R | - | A |
| 成果物・編集案の受け渡し | R | C（検証・取り込み） | A |
| 公開物のデプロイ・反映 | C（編集案作成まで） | R（検証・デプロイ） | A |
| 正本更新（運用メモ・仕様書・スキル） | C（変更案の提示まで） | R（正本反映） | A |
| 個人・機密データを含む作業／定常実行（例外を除く） | 対象外（停止・誘導） | R | A |

※ R＝実行責任、A＝説明責任（最終承認・条件決定）、C＝相談先。

## 1.3 共有フォルダの境界

共有ストレージに次の3つのフォルダを用意する。名前は自分の環境に置き換えること。

| フォルダ | 役割 | 書き込み |
| :---- | :---- | :---- |
| `<shared-drive>/reference` | 参照専用の資料置き場 | 両AIとも書き込み・移動・削除をしない |
| `<shared-drive>/primary-work` | Primary の作業場。作業中の書き込みはここへ | Primary |
| `<shared-drive>/primary-to-secondary` | Primary から Secondary への受け渡し専用。成果物・改訂案・ログ断片を置く | Primary（置くのみ） |
| `<shared-drive>/shared-canonical` | キットと運用メモの正本の置き場。連携物（更新待ち一覧・図解依頼）もここに置く | Secondary（本人承認後のみ） |

正本は1か所だけに置く。コピーを正本として扱わない。

## 1.4 正本管理の考え方

内容は次のとおり。

- 正本（運用メモ・仕様書・スキル定義）は Secondary が管理し、Primary は読み直して取り込むだけとする
- 取り込みとは、作業を始める前に正本の最新版を読み直し、その内容をその作業に適用した状態をいう。読み直していない場合は、記録に「未読」と区別して書く
- 変更は必ず改訂案として出す。改訂案には差分（変更前と変更後）と影響（何が許可され、何が止まるか）を必ず添え、本人の承認を経てから反映する（CHG-01・CHG-02）
- 版は更新のたびに1つ上げ、更新日とあわせて運用メモの冒頭に記録する
- 変更案を起案・反映する時は、変更対象の節だけでなく全文を横断確認し、矛盾する旧記述を同時に書き換える（または削除する）

## 1.5 Primary の担当外（誘導条件）

次のいずれかに触れる依頼が来たら、Primary は自分で処理せず、作業を止めて「この件は Secondary へ持っていってください」と本人へ案内する。理由も1行で添える。

- 個人・機密データを含む作業。含むかどうか判断できない場合も含む
- 正本の作成・変更にあたる作業
- 送信、公開、支払い、申込、削除、権限変更などの承認行為や、元に戻せない変更
- 定常実行の設定、台帳の管理、月次報告など、継続的な管理にあたる作業（v1.0 では自動実行の例外を含めない）
- 依頼が「データの無い単発作業」かどうか、判断に迷う場合
