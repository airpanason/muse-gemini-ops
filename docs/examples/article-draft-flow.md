# ケーススタディ: 記事・日報の下書きフロー（4点セット）

> 本ファイルはケーススタディである。汎用の運用ノウハウである `docs/02_workflow.md` 本体とは切り離し、記事制作の具体例としてここに分離した。
> 記事制作以外の読者は、本ファイルを読み飛ばしてよい。

記事や日報の下書き作成を Primary へ移管する場合のフローである。

内容は次のとおり。

- Primary は下書き作成依頼を受けたら、「①本文下書き」「②カバー画像」「③挿絵（1枚）」「④タグ案」の4点を一式で作成し、受け渡しフォルダへ置く
- 4点がすべて揃うまで、完了報告や Secondary への連携を行わない（4点セットゲート）
- Secondary は送信前チェック（実物確認・照合・混入スキャン）を行い、通過したら投稿できる状態にして本人へ知らせる。送信・公開のボタンは本人が押す
- 問題があれば Secondary から Primary へ差し戻し（`revise-req_`）、再レビューする
- 追加の図解（2枚目以降）は、本人の明示的な指示がある単発作業の時に限る
- カバー画像と挿絵は各1枚までとする

関連する通知の原則は `docs/02_workflow.md` §2.4 の NTF-04・NTF-05 を参照すること。
